# Custom EQ curve implementation plan

> Execute inline with superpowers:executing-plans; one fresh review at the end.

**Goal:** App-like theme-aware EQ curve, automatic verified save on release.
**Spec:** ../specs/2026-10-31-eq-curve-design.md, approved in conversation.
**Architecture:** EqCurveEditor.qml owns gesture/draft/painting; EqCurve.js
owns bounded monotone path math; BarWidget sends the released complete curve
and settles readback. Existing Service/bridge/controller add an optional device
token checked before and after reconnect, with no write replay.
**Tech stack:** Qt Quick/Shapes, existing QML service and Python backend.

## Constraints and review focus

- Device-provided bands/ranges/step; Nord62/250/1k/4k/8k/16k and-6..+6.
- No transmissions while dragging, cancelled/unchanged gestures or hidden UI.
- Preserve active local drag over same-entry polling; cancel on entry/device
  change, disable, close or disconnect. No stale callback can write a new pair.
- Theme accent changes must update line, fill and handles without a restart.
- No overshoot beyond actual band values. New UI reports only verified saves.
- Work in installed fork per user's explicit location; no new worktree needed.
