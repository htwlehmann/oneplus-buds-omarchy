# Publication snapshot design

Approved scope: prepare the existing Nord Buds work locally for a personal
GitHub fork and later contributions; do not push, create a remote fork, open a PR,
change the installed plugin, or promise ongoing maintenance.

Use an independent checkout with the original Git ancestry. Keep runtime Python,
QML/JavaScript and protocol behaviour identical to source commit `dd3a103`.
Correct README, compatibility, publication and fork metadata; retain MIT notices
and distinguish owner hardware evidence from upstream maintainer evidence.

Provide a dated snapshot tag, tested restoration instructions, public evidence
without APK/decompiled sources, a current panel preview, local PR scope notes,
and a verified offline Git bundle. Preserve historical commits unless the
publication audit finds actual private material requiring a separate decision.
Do not copy personal research paths into new public instructions.

The accepted approach is a contribution fork, not a second Marketplace listing.
The existing plugin ID and package version stay unchanged. Public fork repository
metadata points to htwlehmann; upstream attribution remains explicit. Restore
instructions use a pinned tag and export to an absent plugin destination, with
an existing installation backed up outside the plugin discovery directory.
